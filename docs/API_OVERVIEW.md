# API Overview

This is a complete list of every route the backend currently exposes, grouped
by the FastAPI router tag it belongs to. It was generated by inspecting
`backend/app/api/routes/` and the running app's own OpenAPI schema
(`GET /openapi.json`), not written from memory — if a route isn't in this
document, it doesn't exist yet.

For interactive, always-current documentation with request/response schemas,
run the backend and open `http://localhost:8000/docs` (Swagger UI) or
`http://localhost:8000/redoc`.

For hand-written `curl` examples of the Auth, Applications, Clearances,
Documents, and Notifications groups, see
[`backend/README.md`](../backend/README.md) — it predates the Admin,
Registrations, and Official Workspace groups added later, so those three are
documented only here.

**Access column key:** Public = no token required. Student / Official / Admin
= that `account_type` only. Official or Admin = either. Owner = the resource's
own student (others get 404, not 403, so existence is never confirmed to a
non-owner).

## Auth

| Method | Route | Purpose | Access |
|---|---|---|---|
| POST | `/auth/login` | Log in with a student ID, student email, or staff email plus password. Returns a JWT and the current user's role/office info. | Public |
| GET | `/auth/me` | Return the authenticated user's own profile (`account_type`, `role_key`, `role_name`, `is_active`, `must_change_password`). | Any authenticated user |
| POST | `/auth/change-password` | Change your own password. Requires the current password; clears `must_change_password` on success. | Any authenticated user |

There is no self-service signup route. Accounts only come from `POST
/admin/users/students`, `POST /admin/users/officials`, or the seed script —
see [DECISIONS.md](./DECISIONS.md).

## Admin

All admin routes require `role_key == 'system_admin'`.

| Method | Route | Purpose | Access |
|---|---|---|---|
| GET | `/admin/dashboard/summary` | Overview counts (students, active officials, registrations by status), per-office progress, recent activity, and applications needing attention — computed from live data, not cached. | Admin |
| GET | `/admin/users` | Searchable, filterable, paginated list of student and official accounts (`search`, `role`, `status`, `office`, `page`, `page_size`). | Admin |
| POST | `/admin/users/students` | Create a student account. Returns a one-time temporary password. | Admin |
| POST | `/admin/users/officials` | Create an official account with exactly one of the seven canonical offices. Returns a one-time temporary password. | Admin |
| PATCH | `/admin/users/{user_id}` | Edit an existing student or official's profile fields. Does not change office assignment or role. | Admin |
| POST | `/admin/users/{user_id}/activate` | Reactivate a deactivated account. | Admin |
| POST | `/admin/users/{user_id}/deactivate` | Deactivate an account (never a hard delete). An admin cannot deactivate their own account through this route. | Admin |
| PUT | `/admin/officials/{official_id}/office` | Reassign an official's one primary office. | Admin |
| GET | `/admin/audit-logs` | Raw, system-wide audit log, newest first. | Admin |

Account creation always forces `account_type` and role from *which endpoint
was called* — there is no field in either creation payload that can request
`system_admin`.

## Registrations (student draft workflow)

All routes require a student session and only ever operate on that student's
own applications (never another student's, by ID or otherwise).

| Method | Route | Purpose | Access |
|---|---|---|---|
| GET | `/registrations/current` | Return the student's in-progress draft, or 404 if none exists. | Student (owner) |
| POST | `/registrations/` | Start a registration. Idempotent — if a draft already exists, returns it instead of creating a second one. | Student |
| PATCH | `/registrations/{application_id}/sections/{section}` | Save one wizard step's data. `section` is one of `welcome_desk`, `health_services`, `success_center`, `financial_aid`, `business_office`, `residence_life`, `review`. | Student (owner) |
| POST | `/registrations/{application_id}/submit` | Finalize the draft: validates required fields and minimum credit hours, creates the seven clearance records, and returns a `public_safety_instruction` object. | Student (owner) |
| GET | `/registrations/history` | List the student's submitted (non-draft) registrations. | Student |
| GET | `/registrations/{application_id}/clearances` | Clearance list plus the Public Safety instruction for one registration. | Student (owner) |
| GET | `/registrations/{application_id}/documents` | List documents uploaded to one registration. | Student (owner) |
| POST | `/registrations/{application_id}/documents` | Upload a document to one registration (multipart form: `document_type`, `file`). | Student (owner) |

`/registrations` is additive to the older one-shot `POST /applications` (see
Applications below) — both create the same kind of `Application` row and
share the same clearance workflow. Nothing here removes or breaks the
existing endpoints.

## Applications (legacy one-shot submission)

## Documents

| Method | Route | Purpose | Access |
|---|---|---|---|
| POST | `/applications/{application_id}/documents` | Upload a document to an application created through the legacy flow. | Student (owner) |
| GET | `/applications/{application_id}/documents` | List documents for an application. | Owner, or Official/Admin |
| GET | `/documents/{document_id}/download` | Download one document by ID. Raw storage paths are never exposed. | Owner, or Official/Admin |

Allowed types: PDF, PNG, JPEG, DOCX. Max size: 10 MB. See
[`backend/README.md`](../backend/README.md) for the full `document_type`
list and validation rules.

## Official Workspace

| Method | Route | Purpose | Access |
|---|---|---|---|
| GET | `/official/me/dashboard` | Counts for the caller's own office queue (new, ready, claimed by me, completed). | Official |
| GET | `/official/me/queue` | The caller's office queue, with claim state. Office comes from the authenticated user, never a request parameter. | Official |
| POST | `/official/applications/{application_id}/claim` | Claim the caller's office's clearance on an application, so colleagues see it's being worked on. | Official |
| POST | `/official/applications/{application_id}/unclaim` | Release a claim. | Official |
| GET | `/official/applications/{application_id}` | Full application detail for review. | Official or Admin |
| POST | `/official/applications/{application_id}/decision` | Record a decision without needing to know a `clearance_id` — the backend resolves it from the caller's own office. | Official |

This is additive to `GET /officials/me/queue` and `PATCH /clearances/{id}`
below — both styles work; the Official Workspace routes derive the office
role and the target clearance from the session token, the older ones expect
IDs the frontend already has.

| Method | Route | Purpose | Access |
|---|---|---|---|
| GET | `/officials/me/queue` | Same data as `/official/me/queue`, without claim state. | Official |

|---|---|---|---|

## What does not exist yet

These are called out explicitly so nobody assumes they exist:

- No route lets a student or official self-register. Account creation is
  admin-only.
- No route lets an admin create another admin.
- No route deletes a user account — only activate/deactivate.
- No email-sending endpoint or email-invitation flow.
- No endpoint enforces `must_change_password` — the flag is returned by
  `/auth/me` and `/auth/login` and cleared by `/auth/change-password`, but
  nothing currently blocks further API use while it's `true`.
